# คู่มือ: ทำรีพอทรายเดือนแบบเดียวกันให้ลูกค้ารายอื่น
### ConversionFactor MCP · จากรีพอทแสงไทย (Sangthai) ไปลูกค้าใหม่

> อ่านคู่กับ `workflows/monthly_report.md` (ขั้นตอนประจำเดือนของแสงไทย) และ `slides-filler/README.md` (ติดตั้งสคริปต์)
> เขียนจากสิ่งที่ทดสอบแล้วกับแสงไทย รอบ OCT 2026 — ส่วนที่ยัง **ผูกกับแสงไทย** บอกไว้ตรงๆ ในหัวข้อ 3

---

## 1. ระบบทำงานยังไง (ภาพรวม 4 ชิ้น)

```
Meta / Google / LINE API ──► tool get_monthly_report_data ──► JSON "sangthai-slides/1"
                                   (ConversionFactor)                │
                                                                     ▼
                          Google Slides (สำเนารีพอทเดือนก่อน) ◄── Apps Script "SPARK Report" (slides-filler)
```

- **tool** ดึงตัวเลขสดจาก API ของบัญชีโฆษณาที่ผูกกับ org แล้วส่ง JSON (หัวข้อ 7 ของผลลัพธ์)
- **สคริปต์** ใน Google Slides หาช่องจาก "ข้อความอ้างอิง" ไม่ใช่ตำแหน่ง แล้วแทนเฉพาะค่า
- ระบบเติม **ตัวเลข** ส่วนวิเคราะห์ (Key Finding), Creative, Competitor, SEO, รูป เป็นงานทีม

## 2. ลูกค้าใหม่ ต้องมีอะไรบ้าง (เช็กลิสต์)

### 2.1 ฝั่ง ConversionFactor (ไม่ต้องแก้โค้ด)
```
□ สร้าง Organization ของลูกค้า → ได้ organization_id (UUID)
□ ผูก ad account ที่ /admin/orgs/<org_id>/ad-accounts  (ผูกได้หลายบัญชีต่อแพลตฟอร์ม)
    - Meta: ad account id (act_…)  · Google: customer id (xxx-xxx-xxxx)  · LINE Ads: A… (ต้องมี access token + secret key ของกลุ่มบัญชี)
□ Google: บัญชีต้องอยู่ใต้ MCC ที่ระบบใช้ — ไม่งั้น 403 (Link แล้วกด Accept ฝั่งบัญชี)
□ Meta: ใช้ System User token แบบ Never expire (token แบบ User หมดอายุ 60 วัน)
□ LINE OA (ถ้าต้องการเพื่อนสะสม): ใส่ LINE Messaging channel secret + channel access token ของ OA นั้นในหน้า integrations ของ org
□ MCP key ของ org (ที่ /admin/mcp-keys) — key ผูกกับ org จึงเห็นเฉพาะข้อมูลของ org ตัวเอง
```

### 2.2 ฝั่งทีม
```
□ ไฟล์รีพอทเดือนก่อนบน Google Slides (ใช้เป็นแม่แบบ — ทำสำเนา ห้ามแก้ไฟล์กลางตรงๆ)
□ แผนงบรายแพลตฟอร์มของเดือนนี้ (ส่งเป็นพารามิเตอร์ plan)
□ ผู้ตัดสินใจเรื่อง "นิยามตัวเลข" ของลูกค้า (ผลลัพธ์ของแต่ละกลุ่มแคมเปญนับอะไร — ดูหัวข้อ 4)
```

### 2.3 ทดลองด้วยข้อมูลจริงก่อนทำอย่างอื่น
เรียก tool ด้วย `organization_id` ของลูกค้า แล้วดูว่า
1. ทุกบัญชีที่ผูกไว้ดึงได้ (ไม่มีหัวข้อ "ดึงข้อมูลบางบัญชีไม่ได้")
2. หัวข้อ **1. Overview** ยอดรวมตรงกับที่ Ads Manager / Google Ads แสดง (เทียบรอบเดียวกัน)
3. กลุ่มแคมเปญที่ระบบจัดให้ถูกต้องไหม (หัวข้อ 2–4) — ถ้ามีแคมเปญไปอยู่ "other" แปลว่าชื่อไม่ตรงกติกา (หัวข้อ 3)

ถ้าข้อ 1–2 ผ่าน คุณได้ **ตัวเลขรายแพลตฟอร์ม** ใช้ได้แล้ว แม้ยังไม่ได้ทำสไลด์

## 3. ส่วนที่ "ผูกกับแสงไทย" — ต้องปรับเมื่อทำให้ลูกค้าอื่น

ทำงานได้ทันที (ไม่ผูกกับลูกค้า): การดึง API, ช่วงรอบ 16–15, การเทียบรอบก่อน, การคำนวณผลต่าง/สี, ตัวเติมสไลด์, การจำค่าที่ทีมแก้, cache/timeout

**ผูกกับแสงไทย (ในโค้ด ยังไม่ได้ย้ายไปเป็นค่าตั้งค่า):**

| เรื่อง | อยู่ที่ไหน | ที่แสงไทยเป็น | สิ่งที่ต้องปรับ |
|---|---|---|---|
| การจัดกลุ่มแคมเปญ Meta | `classifyMeta` ใน `backend/src/services/monthly-report.ts` | ชื่อขึ้นต้น `ST_Message <สาขา>`, `ST_Pagelike <สาขา>`, มี `Contest`, `Page Like`, `VDO`, `Engage` | แก้ regex ให้ตรงกับการตั้งชื่อของลูกค้า |
| การจัดกลุ่ม Google | `classifyGoogle` (ใช้ชนิดแคมเปญ SEARCH/DISPLAY/VIDEO + คำว่า GMB) | Search / GDN / VDO / GMB | ลูกค้าที่ไม่มี GMB หรือมีกลุ่มอื่น (Shopping, PMax) ต้องเพิ่มกลุ่ม |
| นิยามผลลัพธ์ Facebook | `metaResult` | Message = `onsite_conversion.messaging_conversation_started_7d`, Engagement = `post_engagement`, Page Like = `like` | ลูกค้าที่วัด Lead/Purchase ต้องเปลี่ยน action |
| นิยามผลลัพธ์ Google | ใน `buildMonthlyReport` | conversions (GMB นับ conv, VDO นับ views) | ตามเป้าของลูกค้า |
| หน้าสาขา (17 สาขา) | `branch-details.ts`, `slide-fills.ts` | หัวหน้า "Message Campaign" + ชื่อสาขา | ลูกค้าที่ไม่มีโครงสาขา ข้ามส่วนนี้ได้ (ไม่ส่ง branchDetails) |
| ข้อความอ้างอิงในสไลด์ | `slide-fills.ts` (`containsText`, `titlePrefix`, `label`) | เช่น `Actual Spending`, `Gain Friend Campaign`, `Optimisation goal : …` | ต้องตรงกับถ้อยคำในแม่แบบของลูกค้า (หัวข้อ 5) |
| LINE Ads | `line-monthly.ts` | เพื่อน = คลิกของแคมเปญ objective GAIN_FRIENDS | ปรับถ้าลูกค้าใช้ objective อื่น |
| ชื่อ schema ใน JSON | `SLIDES_SCHEMA = 'sangthai-slides/1'` | ชื่อติดแสงไทย | เปลี่ยนชื่อได้ แต่ต้องแก้ `SCHEMA` ใน Code.gs พร้อมกัน |

> ข้อสรุปตรงๆ: ลูกค้ารายใหม่ที่ **ตั้งชื่อแคมเปญคนละแบบ** หรือ **ใช้แม่แบบสไลด์คนละหน้าตา** ยังต้องมีงานแก้โค้ดเล็กน้อยถึงปานกลาง
> ถ้าจะทำให้ลูกค้า 3 รายขึ้นไป ควรย้ายกติกาข้างบนไปเป็น "ค่าตั้งค่าต่อ org" (config) ก่อน — ตอนนี้ยังไม่ได้ทำ

## 4. ขั้นตอนทำให้ลูกค้ารายใหม่ (ลำดับที่แนะนำ)

1. **ตัวเลขก่อน** (หัวข้อ 2.3) — ผ่านแล้วค่อยไปต่อ
2. **ตกลงนิยามตัวเลขกับทีมลูกค้า** — เขียนลงตาราง: กลุ่มแคมเปญ → ผลลัพธ์ที่นับ → หน้าสไลด์ที่ใช้ (ใช้ `templates/sangthai_report_template_map.md` เป็นตัวอย่าง)
3. **ทำ Template Map ของลูกค้า** — ไล่ดูไฟล์สำเนา ว่าแต่ละหน้ามีกล่องไหนต้องเติม ชนิดช่อง (กล่องข้อความ / ตาราง) และข้อความอ้างอิง
   - เก็บข้อสังเกตแบบที่ทำกับแสงไทย: กล่องเก่าที่ทีมพักไว้นอกสไลด์, ตารางที่มีเซลล์ผสาน, ป้ายที่แยกกล่องจากตัวเลข
4. **ปรับกติกาจัดกลุ่ม** (หัวข้อ 3) แล้วรัน `npm test` + `npx tsc --noEmit` (ใน `backend/`)
5. **เขียน fill op ของหน้าที่ต้องเติม** ใน `slide-fills.ts` ทีละหน้า เริ่มจาก Overview
6. **ติดตั้งสคริปต์บนสำเนา TEST** (`slides-filler/README.md`) และเติมจริง → ดู "เติมแล้ว / ตรงอยู่แล้ว / ข้าม / ไม่พบ"
7. **ตรวจ 5 อย่างก่อนใช้กับไฟล์จริง**: ฟอนต์/สีไม่เพี้ยน · เติมซ้ำ 2 รอบ = "ตรงอยู่แล้ว" ทั้งหมด · พิมพ์ทับบางช่อง = ถูกข้าม · ตัวเลขตรง Ads Manager · เวลารัน < 6 นาที
8. ใช้จริงกับไฟล์กลางเมื่อทีมยืนยัน (แนะนำให้ทำสำเนาทุกเดือนแล้วเติม ไม่แก้ไฟล์กลางตรงๆ)

### บทเรียนจากแสงไทยที่ควรรู้ก่อนเริ่ม
- **ตัวเลขของทีมอาจต่างจากระบบเล็กน้อย** (เช่น Conv. 264.03 กับ 264.53) เพราะ Google ปรับตัวเลขย้อนหลัง — ตกลงกันว่าจะยึดตัวเลขชุดไหน
- **ตัวเลขเพื่อน LINE OA จาก API ต่างจาก OA Manager** (46,976 กับ 47,106) นิยามไม่เหมือนกัน — ให้ทีมเลือกชุดเดียว
- **ป้ายกับตัวเลขอยู่คนละกล่อง** เป็นเรื่องปกติ — ต้องเลือกกล่องจากรูปแบบของตัวเลข ไม่ใช่จากป้ายเสมอไป
- **อย่าเดาโครงสไลด์** — ตรวจจากข้อความที่ export (`/export/txt`) หรือจาก "ผลเติม" ว่าขึ้น "ไม่พบ" ที่ใด
- ตาราง Google/Facebook: จับคู่แถวด้วยชื่อที่ทีมตั้ง แถวที่ไม่มีข้อมูลระบบแจ้งให้ ไม่เดา

## 5. วิธีเขียน fill op ให้หน้าใหม่ (ย่อ)

ใน `slide-fills.ts` แต่ละช่องคือ object หนึ่งก้อน:

```ts
{ id: 'line.gain.count',                       // ชื่อไม่ซ้ำ (ใช้จำค่าที่เติม)
  slide: { containsText: 'Gain Friend Campaign' },   // หาหน้าจากข้อความ
  shape: { containsText: 'Optimisation goal : Gain Friends' },  // หากล่องในหน้านั้น
  label: 'จำนวน', mode: 'after_colon',          // แทนค่าหลัง ":" ของบรรทัดที่ขึ้นต้นด้วยป้ายนี้
  value: '314 ครั้ง (+37%)', tone: 'good' }     // สีเขียว/แดง/เหลือง ของส่วน "(…%)"
```

| mode | ใช้เมื่อ |
|---|---|
| `after_colon` | บรรทัด `ป้าย : ค่า` ← ใช้บ่อยสุด |
| `colon_until_paren` | แทนเฉพาะค่าก่อนวงเล็บ (เก็บ "(แผนที่ตั้งไว้ …)" ของทีม) |
| `after_marker` | ค่าอยู่หลังข้อความคั่นที่ไม่ใช่ `:` |
| `regex` | กล่องที่ไม่มีรูป `ป้าย : ค่า` เช่น กล่องตัวเลขเดี่ยว — ใช้ `shape.matches` เลือกกล่อง และ `pattern` เลือกส่วนที่จะแทน |

ตาราง: `kind: 'table'` + `table.headerContains` + `candidates` (ชื่อแถว → ค่าแต่ละคอลัมน์) — สคริปต์จับคู่แถวด้วยชื่อที่ทีมตั้งและไม่แตะคอลัมน์ชื่อ

**ข้อควรระวังของ regex:** ต้องไม่ไปชนกล่องอื่นในหน้าเดียวกัน — ทดสอบด้วยข้อความจริงของหน้า (ดูตัวอย่างใน `backend/src/services/__tests__/line-oa.test.ts`)

เพิ่มเทสต์ทุกครั้ง: ตัวแทนข้อความของกล่องจริง → ผลที่คาดหวัง

## 6. ใช้งานประจำเดือนผ่าน Claude Desktop

1. ติดตั้ง MCP ของ ConversionFactor ใน Claude Desktop ด้วย key ของ org (ครั้งเดียว)
2. สั่ง: *"เรียก get_monthly_report_data ของ org <…> รอบ <period_end> แผน {facebook:…, google:…, line:…}"*
3. ผลยาว (~65,000 ตัวอักษร) **ห้ามให้ AI พิมพ์ JSON ซ้ำ** (ตัวอักษรไทยเพี้ยนได้) — ให้คัดลอกจากกล่องผลลัพธ์ของ tool หรือจากไฟล์ที่ระบบเก็บให้ แล้วดูว่าขึ้นต้น `{"schema":"…"` และจบด้วย `}`
4. เมนู **SPARK Report → เติมข้อมูลจาก JSON…** → วาง → เติมข้อมูล
5. ตัวเลขที่ API ไม่มี (เช่น LINE OA ข้อความที่ได้รับ/ส่ง/ทักทาย/แอคทีฟแชท) ส่งเป็น `line_oa: { received:{cur,prev}, sent:{…}, greeting:{…}, active_chats:{…} }`

### ถ้า tool ตอบว่าหมดเวลา / รอ
- tool รอผลสูงสุด ~50 วินาที ถ้ายังไม่เสร็จจะตอบว่า "กำลังดึง… เรียกซ้ำด้วยค่าเดิม" — รอ 1 นาทีแล้วเรียกซ้ำ **ด้วยค่าเดิมทุกตัว** จะได้ผลที่ดึงค้างไว้ทันที (เก็บไว้ 10 นาที)
- ถ้าเปลี่ยนค่า (เช่น แผนงบ) จะถือเป็นคำขอใหม่ ต้องดึงใหม่

## 7. Troubleshooting เพิ่มเติม

| อาการ | สาเหตุที่พบ | แก้ |
|---|---|---|
| สคริปต์ขึ้น "ไม่พบหน้า" | กล่องชื่อหน้าอยู่นอกสไลด์ / ข้อความอ้างอิงไม่ตรง | ตรวจ `titlePrefix`/`titleKey`; ระบบเลือกกล่องที่อยู่ในสไลด์ (วัดจากขอบ ไม่ใช่จุดกลาง) |
| "พบหน้า N แต่ไม่พบกล่อง/บรรทัดที่ตรงกัน" | ป้ายกับตัวเลขอยู่คนละกล่อง หรือถ้อยคำเปลี่ยน | ใช้ `regex` เลือกจากรูปตัวเลข หรือแก้ข้อความอ้างอิง |
| "Exception: … เฉพาะในเซลล์ส่วนหัว" | ตารางมีเซลล์ผสาน | สคริปต์รุ่น v3 จับตามตารางที่เห็นจริงแล้ว — ตรวจว่าใช้รุ่นล่าสุด (ดู `SCRIPT_VERSION` ในผลเติม) |
| รันนานหลายนาที | อ่านทีละกล่องซ้ำ | รุ่น v3.1-fast อ่านครั้งเดียวและจำผล (~30 วินาที) |
| ภาษาไทยเพี้ยนตอนวาง JSON | JSON ผ่านการพิมพ์ซ้ำ/ clipboard ผิด locale | คัดลอกจากผล tool ตรงๆ; ถ้าใช้ `pbcopy` ในเครื่อง ตั้ง `LC_ALL=en_US.UTF-8` |
| ตัวเลขเพื่อน LINE OA "ยังไม่พร้อม" | insight ของ LINE ใช้เวลา ~3 วันหลังวันนั้น | รอแล้วดึงใหม่ (ผลอื่นไม่เสีย) |
| ผลเติม "ข้าม N ช่อง (ทีมแก้ไว้)" | ค่าในสไลด์ไม่ตรงกับที่สคริปต์เคยเติม | ปกติ — ติ๊ก "ทับ" เฉพาะเมื่อต้องการใช้ตัวเลขจากระบบ |

## 8. สิ่งที่ยังไม่มี (ควรรู้ก่อนรับลูกค้ารายใหม่)

- TikTok (ยังไม่มี connector), SEO (GA4 / Search Console / Mangools), Creative, Competitor, รูปทุกรูป
- LINE OA: เพื่อนสะสมดึงจาก API ได้; ข้อความที่ได้รับ/ส่ง/ทักทาย/แอคทีฟแชท ต้องกรอกเอง; Broadcast รายข้อความที่ส่งจาก OA Manager ดึงไม่ได้
- การตั้งค่ากติกาต่อ org (ตอนนี้กติกาจัดกลุ่มแคมเปญอยู่ในโค้ด)
- ยังไม่เคยทดสอบกับลูกค้ารายอื่น — ขั้นตอนในคู่มือนี้อิงจากแสงไทย ครั้งแรกที่ใช้กับลูกค้าใหม่ให้เผื่อเวลาปรับ
