### โครงหน้าสาขา (ต้นแบบ — หน้า 45 บางเลน)
```
[ชื่อ]   Message Campaign <tab> <ชื่อสาขา>                      ← key: branch.<id>.title (ใช้ตรวจว่าเป็นสาขาไหน)
[หัว]    Optimisation goal : Conversations                       ← key: branch.<id>.headline (4 บรรทัด)
         งบประมาณ : ฿3,416.29 THB (-39%)
         ราคาต่อหน่วย : ฿16.04 (-35%)
         จำนวน : 213 ครั้ง (-14%)
[ครีเอทีฟ] "1 / Message = 211 / CTR = 5.72%" ×3 กล่อง + รูปครีเอทีฟข้างๆ (ทีมวางรูป)   ← key: branch.<id>.creative.<1..3>
[ตาราง]  Ads Target | Result | CPA | Budget | MoM (Budget)  — 2 ถึง 5 แถว  ← key: branch.<id>.targets
         เรียงตาม Result มาก→น้อย ชื่อแถวคือชื่อ adset มีเลขลำดับนำหน้า "1. "
[คอมเมนต์ทีม] ไม่มีในหน้าสาขา (หน้าสาขาไม่มีกล่อง Key finding) → ปลอดภัยต่อการเติมซ้ำ
```
กฎที่สังเกตได้: จำนวนแถวตาราง Target ไม่เท่ากันทุกสาขา และทุกเดือน · ครีเอทีฟที่แสดง = Top 3 ตามจำนวน Message · Page Like ใช้โครงเดียวกัน (Pagelike = n)

## กติกาตัวเติม (จากการตรวจของ Argon + Codex)
1. เลือกกล่องด้วย **คีย์ที่ผูกไว้ (Alt Text / ตารางคีย์→object id)** ไม่ใช่ตำแหน่ง/ข้อความ
2. ผูกคีย์อัตโนมัติครั้งแรกจากจุดอ้างอิงข้อความ (เช่น กล่องที่ขึ้นต้น "Actual Spending", หน้าที่ชื่อมี "Message Campaign" + ชื่อสาขา) แล้วเก็บ object id เป็น key→id
3. เก็บค่าที่เติมล่าสุดต่อคีย์ ถ้าข้อความในกล่องไม่ตรงค่าที่เติมไว้ = ทีมแก้เอง → ข้ามและรายงาน
4. ตารางล็อกจำนวนแถว (Top N + "อื่นๆ") ไม่เพิ่ม/ลบแถวตอนรัน
5. หน้าสาขา 17 หน้าสร้างไว้ใน Template ล่วงหน้า ไม่ duplicate ตอนรัน
6. เริ่มรันต้องตรวจ token + ช่วงวันที่ 16–15 ก่อน และสรุปจำนวนช่องที่เติมได้/ข้าม
7. % เปลี่ยนแปลงต้องแยก "เปอร์เซ็นต์" กับ "จุดเปอร์เซ็นต์" และรอบก่อน = 0 ใช้ N/A
